# Go 1.18-1.21: Workspace & Toolchain Era

## Visão Geral

Go 1.18-1.21 trouxeram **Generics** (não relacionado a módulos) e features revolucionárias de **desenvolvimento multi-módulo** e **gerenciamento de toolchains**.

**Timeline**:
- Go 1.18: Março 2022 (Generics + Workspaces)
- Go 1.19: Agosto 2022
- Go 1.20: Fevereiro 2023
- Go 1.21: Agosto 2023 (Toolchain Management)

---

## Go 1.18 (Março 2022)

### Workspace Mode

**Maior feature para módulos!**

Trabalhe com **múltiplos módulos** simultaneamente sem `replace` hacks.

```bash
# Antes: Precisava de replace no go.mod
replace github.com/empresa/lib => ../lib

# Agora: Workspace!
go work init ./app ./lib
```

**Arquivo go.work**:
```go
go 1.18

use (
    ./app
    ./library
    ./tools
)
```

**Benefícios**:
- ✅ Desenvolvimento local simplificado
- ✅ Monorepos mais fáceis
- ✅ Sem editar go.mod
- ✅ Cada desenvolvedor tem seu workspace local

Ver capítulo completo: [Workspace Mode](../avancado/workspace-mode.md)

### 🔨 Comandos de Workspace

```bash
go work init <dirs...>     # Criar workspace
go work use <dir>          # Adicionar módulo
go work use -r .           # Adicionar recursivamente
go work edit               # Editar go.work
go work sync               # Sincronizar deps
```

### 🧬 Generics (Não é de módulos, mas revolucionário)

```go
func Min[T constraints.Ordered](a, b T) T {
    if a < b {
        return a
    }
    return b
}
```

### Outras melhorias

- Fuzzing nativo
- Performance de compilação melhorada
- `go mod init` mais inteligente

## Go 1.19 (Agosto 2022)

### Requisitos de dependências em Go 1.19

`go list -m -json` passou a informar o campo `Origin`, com dados sobre a origem do módulo quando disponíveis. Essa informação ajuda a entender de onde veio uma versão.

```bash
go list -m -json rsc.io/quote@v1.5.2
```

Comentários já eram aceitos no `go.mod`. A indicação de módulo depreciado com `// Deprecated:` foi introduzida no Go 1.17.

### Outras melhorias

- Melhorias de segurança
- Redução de alocações
- Suporte a novas plataformas

## Go 1.20 (Fevereiro 2023)

### Comando go em outro diretório

A flag `-C` permite mudar de diretório antes de executar um comando:

```bash
go -C ./app test ./...
```

O Go 1.20 não removeu `GO111MODULE`. O modo de módulos é o padrão desde Go 1.16, mas `GO111MODULE=off` ainda seleciona o modo GOPATH no Go 1.27.

### PGO (Profile-Guided Optimization) Preview

O Go 1.20 introduziu suporte experimental a otimização baseada em perfis:

```bash
go build -pgo=auto
```

Nesse modo, o Go procura `default.pgo` no diretório do pacote principal. O ganho depende do perfil e do programa; no Go 1.21, `auto` passou a ser o padrão.

### Outras melhorias

- Melhores mensagens de erro.
- Performance de compilação.
- Suporte melhorado a CGO.

## Go 1.21 (Agosto 2023)

### 🎯 Gestão automática da Toolchain

**FEATURE REVOLUCIONÁRIA!**

Go agora **baixa automaticamente** a versão correta:

```go
// go.mod
go 1.21
toolchain go1.21.5
```

```bash
# Você tem Go 1.21.0, com GOTOOLCHAIN=auto
$ go build
go: downloading go1.21.5 (linux/amd64)
# Usa Go 1.21.5 automaticamente!
```

**Variável GOTOOLCHAIN**:
```bash
GOTOOLCHAIN=auto     # Padrão: download automático
GOTOOLCHAIN=local    # Usar apenas versão instalada
GOTOOLCHAIN=go1.21.5 # Forçar versão específica
```

Ver capítulo completo: [Toolchain Management](../avancado/toolchain-management.md)

### 🔧 Diretiva `toolchain` 

```go
module example.com/project

go 1.21
toolchain go1.21.5  // Versão recomendada

require (
    github.com/gin-gonic/gin v1.10.0
)
```

### 📦 Toolchains como módulos

Toolchains são tratados como módulos:
- Caminho: `golang.org/toolchain`
- Respeita `GOPROXY`
- Cacheable

### Requisito mínimo na linha go

A diretiva `go` passou a ser um requisito mínimo obrigatório. A seleção de toolchains usa esse requisito e a sugestão de `toolchain`; não é o mesmo algoritmo MVS usado para escolher versões das dependências.

Go 1.19.13+ e Go 1.20.8+ também recusam módulos que exigem Go 1.21 ou superior. Essa verificação foi incorporada às versões anteriores para evitar builds com um toolchain incompatível.

### Outras melhorias

- Experimento `GOEXPERIMENT=loopvar`; a mudança nas variáveis por iteração virou padrão para módulos `go 1.22` ou superior
- `min()` e `max()` built-ins
- `clear()` built-in
- Performance geral melhorada
- PGO estável (não mais preview)

## Workflow moderno (Go 1.21+)

### Desenvolvimento Local

```bash
# 1. Criar workspace para múltiplos módulos
go work init ./service1 ./service2 ./shared

# 2. Toolchain automático garante versão correta
# (Definido em go.mod de cada módulo)

# 3. Desenvolver normalmente
cd service1
go build  # Usa workspace + toolchain correto
```

### CI/CD

```yaml
- uses: actions/setup-go@v5
  with:
    go-version-file: 'go.mod'  # Lê go e toolchain!

# Go baixa toolchain automaticamente se necessário
- run: go build ./...
- run: go test ./...
```

## Migração para Go 1.21+

### Preparação

```bash
# 1. Atualizar Go para 1.21+
# 2. Atualizar go.mod
go mod edit -go=1.21

# 3. Adicionar toolchain (opcional mas recomendado)
go mod edit -toolchain=go1.21.5

# 4. Tidy
go mod tidy

# 5. Testar
go build ./...
go test ./...
```

### Setup do Workspace 

```bash
# Para projetos multi-módulo
go work init ./module1 ./module2

# Adicionar ao .gitignore
echo "go.work" >> .gitignore
echo "go.work.sum" >> .gitignore
```
