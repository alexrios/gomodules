## Go 1.22 (Fevereiro 2024)

### 🔄 go work vendor

Workspace agora suporta vendoring!

```bash
# Criar vendor para o workspace que contém service1 e service2
go work vendor

# Build usando vendor
go build -mod=vendor ./service1/... ./service2/...
```

### 🔧 for loop "fix"

Em módulos com `go 1.22` ou superior, variáveis declaradas pelo loop passam a ter uma instância por iteração:

```go
// Go ≤ 1.21: Bug clássico
for i := range items {
    go func() {
        fmt.Println(i)  // Compartilha a variável do loop
    }()
}

// Go ≥ 1.22: Funciona corretamente!
for i := range items {
    go func() {
        fmt.Println(i)  // ✅ Valor correto
    }()
}
```

### Outras melhorias

- `range` sobre integers
- Melhorias de performance
- Melhor suporte a WASM

## Go 1.23 (Agosto 2024)

### Telemetria

Go 1.23 introduziu o comando `go telemetry`. O padrão é `local`: coleta local, sem envio. O envio depende de ativação explícita.

```bash
# Consultar o modo atual
go telemetry

# Habilitar coleta e envio
go telemetry on

# Manter apenas a coleta local
go telemetry local

# Desabilitar a coleta
go telemetry off
```

### Conferir o tidy sem editar arquivos

```bash
go mod tidy -diff
```

O comando mostra as alterações necessárias em `go.mod` e `go.sum` e retorna status diferente de zero quando há diferenças.

### Outras melhorias

- O analisador `stdversion` foi adicionado ao `go vet`
- Iteração sobre funções passou a fazer parte da linguagem

## Go 1.24 (Fevereiro 2025)

### 🛠️ `tool` directive

**FEATURE MUITO ESPERADA!**

Finalmente, gerenciamento oficial de ferramentas:

```go
// go.mod
module example.com/project

go 1.25

// Dependências de runtime
require (
    github.com/gin-gonic/gin v1.10.0
)

// Ferramentas de desenvolvimento
tool (
    golang.org/x/tools/cmd/goimports
    github.com/golangci/golangci-lint/cmd/golangci-lint
    github.com/swaggo/swag/cmd/swag
)
```

**Comandos**:
```bash
# Adicionar ferramenta
go get -tool github.com/golangci/golangci-lint/cmd/golangci-lint@latest

# Executar ferramenta
go tool golangci-lint run

# Instalar ferramentas
go install tool  # Instala todas no GOBIN
```

Ver capítulo completo: [Tool Dependencies](/avancado/tool-dependencies/)

### 🔐 GOAUTH - Module Authentication

Autenticação para descoberta de módulos via HTTPS e acesso a proxies:

```bash
# Arquivo ~/.netrc ou o arquivo indicado por NETRC (padrão)
export GOAUTH=netrc

# Credential helper do Git, executado nesse diretório absoluto
export GOAUTH="git /home/gopher/projeto"

# Helper próprio
export GOAUTH="/usr/local/bin/auth-helper"
```

Os métodos podem ser separados por `;`. Configure `GOPRIVATE` para indicar os módulos privados e a autenticação do próprio Git quando o download usar esse VCS.

Ver capítulo: [Security Features](/avancado/security-features/)

### 📋 Structured Output (-json flags)

Go 1.24 adicionou `-json` ao `go build` e ampliou o JSON de `go test` com informações de build. `go list -json` e `go test -json` já existiam:

```bash
# go list com JSON
go list -json -m all

# go build com JSON
go build -json ./...

# go test com JSON
go test -json ./...
```

**Benefícios**:
- Parsing fácil em scripts
- Integração com ferramentas
- CI/CD mais robusto

### 🔄 `go run` caching

`go run` agora cacheia executáveis:

```bash
# Primeira execução: compila
go run main.go

# Segunda execução: usa cache
go run main.go
```

### Outras melhorias

- Melhorias no PGO
- Performance geral
- Suporte a novas plataformas

## Go 1.25 (Agosto 2025)

### 🚫 `ignore` directive

Ignore diretórios ao matching patterns:

```go
// go.mod
module example.com/project

go 1.25

// Ignorar diretórios específicos
ignore (
    ./generated
    ./examples/legacy
    deprecated
)
```

**Uso**:
```bash
# ./... agora ignora os diretórios especificados
go build ./...
go test ./...
```

### Subdiretórios em caminhos personalizados

Módulos em subdiretórios já eram suportados. A novidade permite indicar esse subdiretório na resposta `go-import` usada por caminhos personalizados:

```html
<meta name="go-import" content="example.com/lib git https://github.com/org/repo subproject">
```

Aqui, `example.com/lib` aponta para o diretório `subproject` do repositório. O import continua usando o caminho do módulo:

```go
import "example.com/lib"
```

### 🎯 Novo padrão de uso do `work`

Novo pattern para workspace modules:

```bash
# Testa todos os pacotes em TODOS os módulos do workspace
go test work

# Build todos os módulos do workspace
go build work
```

### 📊 `go doc -http`

Servidor de documentação integrado:

```bash
# Iniciar servidor de docs
go doc -http fmt

# Abre automaticamente no browser
# Mostra a documentação do pacote solicitado
```

### 🐳 Container-Aware GOMAXPROCS

Go agora detecta limites de containers (Kubernetes, Docker):

```go
// Antes: GOMAXPROCS = número de CPUs na máquina (ex: 96)
// Mesmo se container limitado a 2 CPUs!

// Go 1.25: GOMAXPROCS = CPUs do container (ex: 2)
// Automaticamente!
```

**Benefícios**:
- Melhor performance em Kubernetes
- Menos contenção
- Uso otimizado de recursos

### 🗑️ Green Tea Garbage Collector (Experimental)

Novo GC experimental, voltado a reduzir o custo de marcação e varredura de objetos pequenos:

```bash
GOEXPERIMENT=greenteagc go build
```

### 🔧 Atualizações em toolchain

- Toolchain não é mais adicionado automaticamente ao atualizar `go` line
- Melhor controle de versões

### Outras melhorias

- Performance do compilador
- Melhorias em generics
- Suporte a novas arquiteturas
- Melhorias no runtime

## Exemplo de organização no Go 1.25

### Trecho de um `go.mod`

```go
module github.com/empresa/api

go 1.25

// Dependências de runtime
require (
    github.com/gin-gonic/gin v1.10.0
    gorm.io/gorm v1.25.10
)

// Dependências indiretas
require (
    github.com/gin-contrib/sse v0.1.0 // indirect
    // ...
)

// Ferramentas de desenvolvimento
tool (
    golang.org/x/tools/cmd/goimports
    github.com/golangci/golangci-lint/cmd/golangci-lint
    github.com/swaggo/swag/cmd/swag
)

// Ignorar diretórios
ignore (
    ./generated
    ./examples/legacy
)
```

### O workflow completo

```bash
# 1. Setup inicial
go work init ./service1 ./service2

# 2. Baixar deps + ferramentas
go mod download

# 3. Instalar ferramentas
go install tool

# 4. Desenvolvimento
go tool goimports -w .
go tool golangci-lint run
go test work  # Testa todos os módulos do workspace

# 5. Build
go build work  # Build dos módulos do workspace
```

## Migração para Go 1.24-1.25

### Preparação

```bash
# 1. Atualizar Go
go install golang.org/dl/go1.25.0@latest
go1.25.0 download

# 2. Atualizar go.mod
go1.25.0 get go@1.25.0

# 3. Migrar ferramentas
go get -tool golang.org/x/tools/cmd/goimports@latest
go get -tool github.com/golangci/golangci-lint/cmd/golangci-lint@latest

# 4. Remover tools.go (se existir)
rm tools.go

# 5. Adicionar ignore se necessário
go mod edit -ignore=./generated -ignore=./examples/legacy

# 6. Tidy
go mod tidy

# 7. Testar
go build ./...
go test work
```

### Configurar GOAUTH

```bash
# Para módulos privados, com credenciais já configuradas em ~/.netrc
export GOPRIVATE="github.com/empresa/*"
export GOAUTH=netrc
```
